## About

<img align="right" src="https://img.shields.io/badge/Status-Available%20for%20Opportunities-8B5CF6?style=flat-square&labelColor=1a0b2e" />

I am a **Software Engineer** focused on designing, building, and scaling systems that operate reliably under real-world production load. My work sits at the intersection of **distributed backend engineering**, **applied artificial intelligence**, and **modern full stack product development**.

**Software Engineering.** I build service-oriented backends with a strong emphasis on correctness, observability, and fault tolerance — designing clean API contracts, enforcing layered architecture boundaries, optimizing database access paths, and instrumenting every critical path with structured logging, distributed tracing, and metrics. I treat system design as a first-class discipline: capacity planning, caching strategy, idempotency, graceful degradation, and backpressure are part of the design conversation, not an afterthought.

**AI / Machine Learning.** I engineer end-to-end ML systems rather than isolated notebooks — data ingestion and validation, feature pipelines, reproducible training, evaluation harnesses, model registries, containerized inference, and continuous monitoring for drift and regression. I work extensively with deep learning architectures, transformer models, retrieval-augmented generation, vector databases, and LLM orchestration, with a consistent focus on latency budgets, cost per inference, and measurable quality gates.

**Full Stack Development.** I ship complete products from schema to interface — typed React frontends built for accessibility and performance, component systems that scale across teams, server-rendered applications with disciplined data-fetching and caching layers, and real-time interfaces backed by event-driven infrastructure. I care about Core Web Vitals, bundle discipline, and interaction design that respects the user's time.

**Product Engineering Mindset.** I optimize for outcomes, not output. Every architectural decision is traced back to a user impact, a business constraint, or a reliability target. I write documentation and ADRs, instrument features with analytics before launch, iterate against real telemetry, and prefer boring, well-understood technology over novelty wherever it protects the roadmap.
